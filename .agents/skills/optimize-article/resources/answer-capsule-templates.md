# Answer Capsule Templates (GEO / AEO)

Ready-to-use patterns for creating high-impact Direct Answer Capsules and structured takeaways that AI search engines (Perplexity, ChatGPT, Google AI Overviews) frequently quote and cite.

---

## Pattern 1: The Executive TL;DR Blockquote

Place this immediately after the narrative opening hook (within the first 2-3 paragraphs):

```markdown
> [!NOTE]
> **The Bottom Line (TL;DR)**:
> In AI-assisted software engineering, traditional method-level unit tests fail because agents rewrite both implementation and assertions simultaneously. Sustainable reliability requires shifting verification upstream to behavioral specifications and downstream to integration evaluations.
```

---

## Pattern 2: Key Takeaways Callout

Place this near the top or as a standalone H2 section:

```markdown
## Key Takeaways at a Glance

- **The Problem**: AI code generation creates an illusion of correctness ("green tests") by generating assertions that conform to newly written bugs.
- **The Shift**: Move from method-level unit testing to contract-level behavioral testing.
- **The Solution**: Humans own and review executable specifications; AI agents implement code and ephemeral internal harnesses.
```

---

## Pattern 3: The Comparison Matrix (High Citation Weight)

AI search engines love rendering tables in response to "versus" queries:

```markdown
| Dimension | Traditional Engineering | AI Artisan Era |
| :--- | :--- | :--- |
| **Unit of Testing** | Private/public method or class | Invariant system behavior / contract |
| **Test Author** | Human engineer (TDD) | Human writes spec, agent drafts tests |
| **Review Focus** | Line-by-line syntax & diffs | Specification fidelity & system invariants |
| **Failure Mode** | Compilation error, broken logic | False-positive green test suite |
```

---

## Pattern 4: Definitional Callout

When introducing or redefining a core industry concept:

```markdown
> **Spec-Driven Engineering**: An architectural paradigm where behavioral invariants and acceptance contracts serve as the primary source of truth, treating low-level code implementations as disposable artifacts generated by automated systems.
```
